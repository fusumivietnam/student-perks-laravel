# SWOT — Student Perks Hub source and delivery workflow (2026-11-07)

**Evidence scope:** GitHub `main` at `7c29ea1` before this optimization PR; `Dockerfile`, `compose.yaml`, `.devcontainer/devcontainer.json`, `.github/workflows/ci.yml`, `composer.json`, `package.json`, M0–M4 issues and Codespaces rebuild logs provided by the owner. Ratings are engineering judgments, not measured business KPIs.

| Strengths (internal) | Weaknesses (internal) |
|---|---|
| Core Laravel/Filament CMS, PostgreSQL relations/publication guards and public discovery already exist; CI exercises test and Docker HTTP paths | No completed browser-based mobile/keyboard acceptance; the admin→publication flow is not yet verified end-to-end on real editorial content |
| Small server-rendered Blade/Tailwind stack; no paid hosted backend or SPA infrastructure | Preview originally required manual commands after each merge; revision label before apt/PHP build invalidated expensive Docker cache |
| Private Codespaces port, explicit admin access, no default credentials or public registration | Full heavyweight Docker build on both PR and main; existing CI has no shared Docker layer cache |
| Lockfiles, native framework building blocks, production-minded Nginx and persistent volumes | Brand/media presentation still uses generated initials when logos/assets are missing; demo content is not verified commercial inventory |

| Opportunities (external / next steps) | Threats (external / operational risks) |
|---|---|
| Automate safe Codespaces main updates, reuse Docker cache and make visual review repeatable | Frequent merges can create queue/compute cost, especially on Codespaces if live auto-sync rebuilds per commit |
| Test genuine offers with editorial audit before launch; improve cards, images and conversion paths through existing CMS | Unverified offer claims/expiry/partner links create reputational and content liability |
| Use built-in GitHub Actions cache, Project #5, Laravel/PHPUnit/Pint and a narrow docs reference register | Dependency advisories, container base image drift, npm/Composer security updates |
| Keep production portable across a single VPS or standard container host when authorized | Loss of Codespace destroys preview volumes; production backups/restore, TLS, DNS and legal copy remain unaccepted |

## Priorities and mitigations

- **P0 — stop expensive rebuild loops:** put source SHA metadata after cached dependencies, use PR/main Docker Buildx cache, and trigger only on changed Git revisions. Watcher must skip non-main and dirty worktrees; no force push/reset and no volume deletion.
- **P0 — avoid manual two-command cycle:** Codespaces lifecycle starts an opt-out background watcher; log/status/stop commands are available. It fetches every 5 minutes, but builds only after a new verified fast-forward revision, not on every poll.
- **P1 — close M2 genuinely:** review desktop/mobile/keyboard flows, apply search filters, open offer partner link, validate Filament save/draft/publish from the browser. CI green does not constitute user acceptance.
- **P1 — source and dependency traceability:** keep Composer/npm lockfiles, an official-links reference index and decision notes for non-obvious technical choices; do not add speculative documentation framework or dependency.
- **P2 — M4 production gate:** use real verified partner/legal content and an authorized deployment target, require backup/restore rehearsal and production secrets handling before launch. Do not deploy automatically from Codespaces.

## Critical caveats

- The Codespaces resource numbers (approx. 5.5 GiB available RAM and 25 GiB disk remaining) showed no steady resource bottleneck; rebuilding PHP extensions accounted for most of one 141-second build. This is not a measured guarantee for all future runs.
- Fixing the Dockerfile build arg should stop PHP extension recompilation on *subsequent cache-warm builds*. The first build after changing Dockerfile may still pay a one-time cost. GitHub Actions cache download/upload overhead can vary.
- Auto-sync is active only while an existing private Codespace is running and its startup hooks have executed. It does not remotely start a stopped Codespace or apply production deployments.
